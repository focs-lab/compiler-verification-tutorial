A Lean 4 port of the EUTypes 2019 summer school course

Proving the correctness of a compiler

Original Coq course by Xavier Leroy

Collège de France and Inria Paris

Abstract

Formal semantics is not only a tool for reasoning about individual programs. It also lets us reason about the tools that transform programs — compilers and static analysers — and state precisely what it means for them to be correct. With a proof assistant we can then discharge those statements, and so replace trust in a compiler with a theorem about it.

The course develops this on a small but complete example: a compiler from IMP, a simple imperative language, to a stack machine, together with two dataflow optimizations. The original development was carried out in Coq; this is a translation of it into Lean 4, with all proofs and explanatory text rewritten for Lean.

Everything is proved. There is no sorry in the library, and the headline theorems depend only on Lean's three standard axioms (propext, Classical.choice, Quot.sound). The development has no dependencies beyond Lean's core library — not even Mathlib — so it builds in seconds.

  • Compil: the compiler and its correctness proofs.
  • Constprop: an optimization: constant propagation.
  • Deadcode: another optimization: dead code elimination via liveness analysis.
  • Fixpoints: more on fixpoints and static analysis.
  • Exercises: the exercises of the original course, restated for Lean.

The main theorems

Semantic preservation, for terminating and for diverging source programs (in Compil):

theorem compileProgram_correct_terminating {s c s'} (h : cexec s c s') :
    machineTerminates (compileProgram c) s s'

theorem compileProgram_correct_diverging {c : com} {s : Store}
    (h : Infseq step (c, .stop, s)) : machineDiverges (compileProgram c) s

Semantic preservation for the two optimizations (in Constprop and Deadcode):

theorem cpCom_correct_terminating : ∀ (c : com) {s₁ s₂ : Store} {S₁ : AStore},
    cexec s₁ c s₂ → Matches s₁ S₁ → cexec s₁ (cpCom S₁ c) s₂

theorem dce_correct_terminating {s c s'} (h : cexec s c s') :
    ∀ (L : IdentSet) (s₁ : Store), agree (live c L) s s₁ →
    ∃ s₁', cexec s₁ (dce c L) s₁' ∧ agree L s' s₁'

Notes on the port

The definitions and theorem statements follow the Coq sources; the proofs and prose are new. Three places where Lean pulled the development in a different direction:

  • Divergence. Coq uses a CoInductive predicate. Lean 4 has no coinductive types, so Infseq is defined directly as the greatest fixpoint — the existence of an invariant closed under one transition — which makes the coinduction principle fall out as the definition.
  • Finite maps and sets. Coq's FMaps and FSets have no counterpart in Lean's core library, so abstract stores and variable sets are association lists and plain lists. This also changes the well-foundedness argument in Fixpoints: instead of a finite map's cardinal, the measure is the length of the deduplicated key list.
  • Program-counter arithmetic. Coq's eauto with code and autorewrite with code have no Lean equivalent, so the correctness lemmas take the target program counter as a variable constrained by an equation, leaving omega to do the arithmetic.

See README.md for the full list.
